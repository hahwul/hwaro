### Fixed
- `hwaro build --cache` deletes the output of pages that went away. A cold build starts from an empty output directory, but `--cache` keeps it and the render phase only walks pages that still exist — so a post you deleted, renamed, moved to a new URL (`slug`/`path`/permalink), turned into a draft, let expire, or set `render = false` kept its HTML in `public/`, still answering 200 and still shipping with `hwaro deploy`. Every cache entry records the file its page wrote, so the entries no live page claims name exactly what to remove (`hwaro serve` already did this; the cold `--cache` path never did). Everything the page brought with it goes too: its `aliases` redirect stubs, its AMP mirror, its auto-generated OG image, the taxonomy term page (and feed) of a tag nobody uses any more, and the pagination page a section no longer fills — so a `--cache` build's output is byte-identical to a clean build's, and `--full` is no longer needed to clear anything. Switching a feature off (`[amp] enabled = false`) removes what it used to publish for the same reason
- `--cache`: a page turned `render = false` renders nothing, so `pages_rendered` stayed 0 and the "nothing changed" skip left it in `sitemap.xml`, `rss.xml`, `search.json` and `llms.txt` until an unrelated edit. `render` now counts toward the page-set fingerprint, like `draft`
